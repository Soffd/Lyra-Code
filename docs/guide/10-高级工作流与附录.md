## 18. 高级工作流示例


### 18.1 在手机上维护一个开源插件项目

```text
1. 工作区 = 插件仓库目录，创建 TODO：改代码 → 补测试 → 更新 README → 推送
2. 用 search_files + read_file 熟悉现有代码与 README 结构
3. edit_file 精确修改插件逻辑，run_command 跑回归测试
4. 更新 README 追加「更新日志」条目
5. git add -A && git commit -m "..." && git push（你确认后执行）
6. 汇报：改动点、测试结果、推送状态
```

### 18.2 逐章写作小说 + 进度管理

```text
1. 项目目录放「写作计划.json」与章节正文，AGENTS.md 约定字数口径与命名规则
2. 每章任务：先读上一章结尾与计划 → 创作正文 → 更新计划文件（completed/字数/寿命曲线）
3. 利用记忆保存设定（主角寿命、卷结构、基调），跨会话保持一致
4. 定期用定时任务生成进度总结
```

### 18.3 本地网站开发与预览

```text
1. Termux 中安装 node/npm，工作区初始化 Vite/VitePress 项目
2. 写代码、构建静态产物
3. manage_mini_server(action=start, port=8080) 启动预览
4. 浏览器调试，read_mini_server_logs 排查 404 与 JS 报错
5. 修改后重新构建，停服收尾
```

### 18.4 邮件 + 云盘自动化

```text
1. 配置 IMAP/SMTP 与 WebDAV 账号
2. 让 AI 列出未读邮件 → 提取关键信息 → 生成回复草稿（save_email_draft）
3. 你审阅草稿后手动发送
4. 重要附件下载到隔离目录，杀毒后使用
5. 定期 export_backup 到 WebDAV
```

### 18.5 多 Agent 并行调研（子代理）

```text
1. 把「调研 A 技术方案」与「调研 B 技术方案」拆成两个独立子任务
2. 各自产出：结论、证据来源、风险、建议
3. 主代理复核两份结果，交叉验证冲突点
4. 汇总结论与取舍，输出到工作区文档
```

### 18.6 安全审查清单（每次执行前自检）

```text
□ 这个操作需要什么权限？有没有更低权限的替代？
□ 目标路径/服务器/账号是否正确？
□ 命令会修改什么？能否恢复（备份）？
□ 涉及密钥/隐私吗？会不会被记录或外发？
□ 审批弹窗里的内容和我预期的一致吗？
```

## 19. 附录


### 19.1 常用工具速查

| 想做什么 | 用哪个 |
| --- | --- |
| 列出目录 | list_directory / global_list_directory |
| 找文件 | search_files（工作区）→ global_search_files（全盘） |
| 读文件 | read_file / read_file_lines（大文件分段） |
| 新建/改写文件 | write_file（新文件）/ edit_file（精确改）/ append_file（追加） |
| 下载 | download_file（优先于 curl/wget） |
| 跑命令 | run_command（Termux） |
| 系统操作 | execute_shell_command（Shizuku）/ execute_root_command（root） |
| 联网查资料 | web_search → read_web_page → mark_web_sources |
| 远程 Linux | list_ssh_servers → ssh_exec |
| 邮件 | list_email_accounts → list_emails → read_email / save_email_draft |
| 云盘 | list_webdav_servers → webdav_list / upload / download |
| FTP/SFTP | list_file_transfer_servers → file_transfer_* |
| 本地站点预览 | manage_mini_server + read_mini_server_logs |
| 定时任务 | manage_scheduled_tasks |
| 备份 | export_backup / import_backup |
| 设备信息 | get_device_hardware_info / list_installed_apps |

### 19.2 术语表

| 术语 | 含义 |
| --- | --- |
| 工作区（Workspace） | 原生文件工具允许操作的项目目录，路径相对化 |
| 全局存储（Global） | `/storage/emulated/0` 共享存储，需 global_* 工具 |
| Termux | Android 上的终端模拟器，提供 Shell 命令通道 |
| Shizuku | 通过 ADB 授权的高权限 Shell 服务 |
| MCP | Model Context Protocol，AI 与外部工具/数据源的标准协议 |
| Skill | 包含 SKILL.md 与资源的可选能力包 |
| AGENTS.md | 项目根目录的指令文件，AI 动工前自动读取 |
| .bak | 编辑器覆盖修改前自动生成的同目录备份 |
| Mini Server | 内置静态 HTTP/HTTPS 服务器 |
| 隔离目录 | 附件下载的安全隔离区，AI 不读取其中内容 |
| 补充导入 | 非破坏、自动去重的备份恢复模式 |

### 19.3 许可证与贡献

- 项目采用双重许可：原创代码 AGPLv3-or-later；闭源分发/私有修改/商业例外需商业许可；
- 接受组织成员 PR，AI 辅助代码亦可提交，但提交者需完成测试与人工审查；
- 不要提交签名密钥、keystore、API Key、`.env`、`local.properties` 等隐私文件。
