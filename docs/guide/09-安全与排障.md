## 16. 安全实践与权限控制


### 16.1 权限最小化

- 用不到的系统工具在「Agent 工具页」禁用（如不需要 Root 就不启用 Root 工具）；
- Termux、Shizuku、Root 三档权限按需开启，不为了单条命令越级授权；
- 文件管理器的「所有文件访问」仅在需要全盘管理时授予。

### 16.2 凭据与密钥

- API Key、SSH 私钥、邮箱应用专用密码、MCP Token 都只存本机，备份默认不导出；
- 不要在对话里明文粘贴私钥后发送给第三方服务；
- 含密钥的备份文件必须单独加密保管。

### 16.3 网络与明文

- HTTP 明文 API / MCP / WebDAV / FTP / 微型服务器，数据可能被中间人读取；
- 公网、内网穿透、局域网暴露前：检查服务目录、认证、HTTPS；
- 联网搜索黑名单：精确匹配域名，`*.x.com` 拦子域名，同时填 `x.com` 与 `*.x.com` 可全拦。

### 16.4 命令与远程操作

::: warning 高危操作审查
- `run_command` 没有固定白名单，只拦截明显高危模式（`rm -rf /`、写 `/dev/block`、`mkfs` 等），**审批前务必人工审查**；
- 远程脚本、MCP Server、Skills 仓库、SSH 命令的信任判断由你自己负责；
- 附件只进隔离目录，扫描后再打开；
- 只预览可信的本地 HTML（浏览器脚本会以浏览器权限执行）。
:::

### 16.5 审批策略

::: tip 审批三问
- 阅读审批内容：谁在调用什么工具、读写哪个路径、执行什么命令；
- 发现可疑调用直接拒绝，并告诉 AI 原因；
- 对敏感操作（邮件发送、远程写操作、删除）养成二次确认习惯。
:::

## 17. 常见问题与排查


### 17.1 run_command 不可用/自动禁用

- 检查 Termux 是否允许外部应用调用（见 2.3 节），执行后 `termux-reload-settings`；
- 检查 Lyra Code 设置页的 Termux 权限开关。

### 17.2 文件工具报「路径越界」

- 原生工具只接受工作区内相对路径，绝对路径（如 `/storage/emulated/0/...`）请改用 global_* 工具或确认工作区选择正确；
- 不要把 Termux 私有路径传给原生工具。

### 17.3 edit_file 提示「匹配数不符」

- 目标文本不唯一或已变化：重新读取文件，改用行区间或更长的唯一上下文；
- 不要盲改后反复重试，先读文件确认现状。

### 17.4 命令输出被截断

- stdout/stderr 超过可见范围时，把输出重定向到文件：`cmd > out.txt 2>&1`，再用 read_file 读取；
- 或缩小查询范围（`head` / `tail` / `rg` 精确匹配）。

### 17.5 微型服务器 404 / 页面异常

- 看 `read_mini_server_logs`：404 说明路径不对，auth 失败说明认证不匹配，JS 报错说明脚本问题；
- SPA 路由 404 开 spa_fallback；
- 确认服务根目录确实包含你想要的静态文件。

### 17.6 定时任务没触发

- 检查任务启停状态与计划参数（时区、星期映射 1=周一）；
- 手机电源管理/杀后台会影响触发，必要时加系统白名单；
- 任务提示词中写明输出位置与格式，方便事后核对。

### 17.7 邮件发送失败

- SMTP 需要应用专用密码而非登录密码（多数邮箱）；
- 检查 IMAP/SMTP 端口与加密方式（SSL/STARTTLS）；
- 确认发送前已完成确认流程，重复或不确定的投递不会被自动重试。

### 17.8 WebDAV/FTP 连不上

- 先 `webdav_list` / `file_transfer_list` 看根目录是否可达；
- 检查地址协议（https/davs/ftps/sftp）、端口、用户名、被动模式；
- 凭据变更后重新 list 获取最新 id。
