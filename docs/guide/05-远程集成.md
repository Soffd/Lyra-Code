## 8. 远程集成：SSH / 邮件 / WebDAV / FTP / MCP


远程工具都遵循同一套模式：**先列账号，再操作**。每个账号凭据都保存在本机。

### 8.1 账号管理总则

- 所有远程配置（MCP、SSH、邮件、WebDAV、FTP/FTPS/SFTP）都通过「配置管理」维护；
- 添加账号时，缺失的 Key、密码、应用专用密码、私钥必须由你提供，AI **不会凭空捏造**；
- 身份不明确时先 `list` 查看已有账号，再按返回的 id 操作；
- 凭据变更后，旧会话中的账号 id 可能失效，需重新 list。

### 8.2 SSH

```text
list_ssh_servers → ssh_exec(server_id, command)
```

- 支持密码或密钥登录 Linux / Windows / Git 服务器；
- 每次执行命令都需确认；
- 在远程装软件、改服务、改配置前，先检查操作系统、CPU/内存/磁盘/权限；
- 读日志先看大小和行数，只读小范围：`ls -lh app.log && tail -50 app.log`；
- 避免交互式程序（vim、top、嵌套 ssh）；
- 不要在一条命令里把安装、修改、启动全部串联，分步确认。

### 8.3 邮件（IMAP / SMTP）

```text
list_email_accounts → list_email_folders → list_emails → read_email / save_email_draft / send_email
```

- **读信不改状态**：read_email 不会把邮件标记为已读；
- 正文读取只返回文本，内联媒体与附件字节会被省略；
- 附件下载只进入**隔离目录**，AI 不会读取内容，请用可信杀毒软件扫描后再打开；
- 发送（send_email）**每次都要单独确认**，且不会自动重试可能重复的投递；
- 更稳妥的做法是存草稿（save_email_draft 写入 IMAP 草稿箱），你审阅后再手动发送；
- 不要回复「当前配置账号自己发来的邮件」。

### 8.4 WebDAV

```text
list_webdav_servers → webdav_list / webdav_search / webdav_download_to_workspace / webdav_upload_from_workspace
```

- 优先用 `webdav_list`（PROPFIND）看目录结构，而不是搜索 "."；
- 支持云备份：备份可直接导出到 WebDAV。

### 8.5 FTP / FTPS / SFTP

```text
list_file_transfer_servers → file_transfer_list / file_transfer_search / 上传 / 下载
```

- 目录列举、搜索、上传、下载都可用；
- 凭据与被动模式等参数在配置中维护。

### 8.6 MCP：客户端与服务端

**作为客户端**：

- 支持连接远程 MCP Server：Streamable HTTP 或 SSE；
- MCP 工具运行在外部服务器上，**不自动拥有工作区访问权**，每次调用都需批准；
- 配置时要提供服务器地址、必要的 Token/认证信息。

**作为服务端**：

- 把当前启用的本地工具与已连接的 MCP 工具，通过本机/局域网 HTTP 暴露给其他 MCP 客户端；
- 支持自定义端口与可选认证 Key；
- 暴露到局域网意味着其他设备可访问，务必设置认证 Key；公网暴露风险更高。

### 8.7 自然语言配置管理

你可以直接用中文让 AI 添加/更新/启用/禁用/删除远程配置，例如：

```text
添加一个 WebDAV 账号：https://dav.example.com，用户名 alice，密码 ******
把 SSH 服务器「nas」的密钥更新为新的私钥内容
禁用 FTP 账号 server-02
```

AI 会先列出当前配置确认身份，再执行变更。
