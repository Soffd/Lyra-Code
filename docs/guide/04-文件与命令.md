## 6. 文件操作与代码编辑最佳实践


### 6.1 编辑原则

1. **先读后改**：改动前先读取相关文件、附近代码、README、构建脚本；
2. **小步精确**：用 edit_file 做「唯一文本匹配」或「精确行区间」替换，避免整文件盲写；
3. **复用约定**：沿用仓库已有风格、工具函数、构建命令，不臆造依赖；
4. **验证收尾**：跑最相关的测试/构建/lint，再汇报结果。

### 6.2 编辑工具选型

| 场景 | 工具 | 关键点 |
| --- | --- | --- |
| 创建新文件 | write_file | 同时支持 content 或 content_lines（JSON 数组） |
| 精确替换 | edit_file | old_content 必须唯一，expected_replacements 不匹配会拒绝写入 |
| 行区间替换 | edit_file(start_line/end_line) | 1-based 闭区间，适合大段改动 |
| 追加内容 | append_file | 文件末尾追加 |
| 移动/重命名 | rename_move | 工作区内 |
| 删除 | delete_file_or_folder | 只删文件或空目录 |
| 大文件 | read_file_lines | 先读片段再定位编辑 |

### 6.3 内容搜索技巧

```bash
# 首选：ripgrep（快、输出干净）
rg -n "TODO|FIXME" --glob '*.kt'

# 回退：grep
grep -rn "TODO" --include='*.kt' .

# 只看命中的行号与片段，输出过长时用 head 截断
rg -c "pattern" . | head -50
```

### 6.4 修改回滚

- 覆盖修改前，Lyra Code 会自动在原目录生成 `.bak` 备份（例如 `main.kt.bak`）；
- 编辑器的未保存修改会在退出时提示；
- 对重要文件，可要求 AI 先备份再修改：`cp file file.bak` 或直接说明「改前先备份」。

### 6.5 项目指令文件（AGENTS.md）

在项目根目录放置 `AGENTS.md`（或 `AGENT.md`），AI 在动工前会自动读取，并遵守其中约定：

```markdown
# 项目约定
- 构建命令：./gradlew assembleDebug
- 测试命令：./gradlew test
- 风格：Kotlin，2 空格缩进，禁止魔法数字
- 涉及 secrets 的操作一律拒绝
```

指令文件按目录层级生效：深层目录的规则覆盖浅层，但永远不能覆盖你的直接要求和基础安全规则。

## 7. 命令执行：Termux / Shizuku / Root


### 7.1 三条通道的权限阶梯

| 工具 | 身份 | 适用场景 | 前置条件 |
| --- | --- | --- | --- |
| run_command | Termux 应用用户 | 构建、Git、脚本、包管理、内容搜索 | Termux 已授权 |
| execute_shell_command | Shizuku Shell（ADB 级别） | pm / cmd / dumpsys / 受保护路径 | 已安装并授权 Shizuku |
| execute_root_command | root（su） | 系统文件、/data、系统包管理 | 已 root 且配置 su |

::: warning 权限纪律
**不要为了通过命令而升级权限**。能用 Termux 解决的就不动用 Shizuku/Root。
:::

### 7.2 run_command 使用要点

- 默认工作目录是当前所选工作区，不需要 `cd`；跨目录操作用 `workDir` 参数或绝对路径；
- 多行/缩进敏感的命令用 `command_lines` 数组传入；
- 用 `&&` 串联有依赖的步骤（前一步失败则停止），独立命令分开；
- 交互式程序不要运行；长驻服务用 `background=true`（会返回 launcher_pid 和输出文件）；
- 后台启动**不代表进程健康**，需另用前台命令检查进程/日志；
- 超时 5–600 秒；输出过长时把结果重定向到文件再读取：`cmd > out.txt 2>&1`；
- 高危操作（`rm -rf /`、写 `/dev/block`、`mkfs` 等）会被拦截，但审查仍需人工把关。

### 7.3 安全命令示例

```bash
# 安全的查找删除：先列出再删
find . -name '*.tmp' -type f

# 检查磁盘占用
du -sh * | sort -h | tail -20

# 克隆仓库（需要网络与 git）
git clone --depth 1 https://github.com/Soffd/Lyra-Code.git

# 输出过长时落盘再读
rg -n 'error' --glob '*.log' . > /storage/emulated/0/Lyra/rg.out; wc -l /storage/emulated/0/Lyra/rg.out
```

### 7.4 破坏性操作纪律

- 执行前：解析并核对**确切目标路径**，把范围缩到最小；
- 优先可恢复操作（重命名而非删除、`.bak` 备份）；
- 删除前先 `ls -la` 确认目标；
- 任何失败先读错误分类，换参数重试，而不是盲目重跑同一命令。
